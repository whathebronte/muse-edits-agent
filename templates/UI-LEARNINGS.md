# UI learnings

The living notebook behind the design system. `DESIGN-SYSTEM.md` is the spec: the rules as they stand now. This file is where those rules come from: the owner's feedback, corrections and verdicts, kept with their dates and reasoning.

## How the agent keeps this file

- Read this file before building or editing any space, alongside `DESIGN-SYSTEM.md`.
- Whenever the owner corrects something, states a preference, or rules on a design question, add an entry here in the same session. Do not wait to be asked.
- One entry per learning: date, topic, what the owner said or what went wrong, and the rule going forward.
- Dedupe before writing. If a new entry supersedes an old one, correct the old entry in place and note what replaced it. Never leave two conflicting rules active.
- When a learning hardens into a standing rule that any new space should follow, distill it into `DESIGN-SYSTEM.md` in plain present tense, and mark the entry here as promoted.
- This file is personal: it accumulates the owner's taste and their spaces' history. It is not part of the shareable design spec.

## Entry format

```
### YYYY-MM-DD — topic
What happened / what the owner said.
Rule going forward: ...
```
